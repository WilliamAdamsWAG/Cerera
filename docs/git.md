## Установка Git

### Установка на Windows

Чтобы установить Git на Windows нужно просто перейти по ссылке - [переходник на Git установщик](https://git-scm.com/download/win)

После этого загрузка Git начнется автоматически

Далее запускаете установленный исполняемый файл `(.exe)`

Проходите процесс установки, выбираете желаемый текстовый редактор. Остальные настройки можно не менять.

## Первая настройка

После установки Git нужно провести первую настройку конфига.

Для этого требуется открыть командную строку в вашей ОС и прописать две команды.

Первая настроит ваше имя пользователя

`git config --global user.name ¨ваше имя здесь¨`

Вторая настроит вашу почту, которая будет использоваться в Git

`git config --global user.email ¨ваша почта здесь¨`

## Создание репозитория в Git

Откройте терминал (командную строку)

Перейдите в папку проекта, используя команду

`cd /путь/к/проекту`

Инициализируйте внутри нее репозиторий

`git init`

!!! info "Примечание"
    После использования данной команды внутри папки проекта будет создана скрытая папка `.git`, где Git будет хранить всю историю изменений.

## Запись изменений в репозиторий

После того, как вы добавили какие-то новые файлы в свой проект их нужно записать в репозиторий.

Чтобы проверить какие файлы были модифицированы/добавлены/удалены нужно использовать команду `git status`

Если репозиторий был только создан, то вывод будет выглядеть примерно так:

```
> git status

On branch master
Your branch is up-to-date with 'origin/master'.
nothing to commit, working tree clean
```

Если же какие-то файлы были отредактированы:
```
> git status

On branch master
Your branch is up-to-date with 'origin/master'.
Untracked files:
  (use "git add <file>..." to include in what will be committed)

    README

nothing added to commit but untracked files present (use "git add" to track)
```

Здесь видно какие файлы неотслеживаемые. Эти файлы Git не добавит в изменения репозитория, если его об этом не попросить вручную.

Чтобы добавить файл в отслеживание нужно использовать команду `git add названиефайла`

Пример:
```
> git add README

> git status

On branch master
Your branch is up-to-date with 'origin/master'.
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)

    new file:   README
```

Так можно заметить, что появился новый файл в списке изменений.

Если файл был не добавлен, а модифицирован, то его можно добавить в изменения тем же путем.

Также можно добавлять сразу все файлы в список изменений (которые были добавлены/модифицированы/удалены). Для этого нужно ввести команду `git add .`

Если нужно убрать индексацию какого-либо файла, то используйте команду `git reset HEAD <файл>`

## Игнорирование файлов

Бывают случаи когда некоторые файлы, которые не хочется видеть в списке изменений или в самом репозитории при отправке изменений. Для этого можно использовать волшебный файл `.gitignore`, который позволяет скрывать от Git нужные папки или файлы, которые указаны в списке игнорирования.

Для этого нужно просто создать файл с названием `.gitignore` и прописывать в нем все нужные вам игнорируемые файлы

Пример:

```
# Исключить все файлы с расширением .a
*.a

# Но отслеживать файл lib.a даже если он подпадает под исключение выше
!lib.a

# Исключить файл TODO в корневом каталоге, но не файл в subdir/TODO
/TODO

# Игнорировать все файлы в каталоге build/
build/

# Игнорировать файл doc/notes.txt, но не файл doc/server/arch.txt
doc/*.txt

# Игнорировать все .txt файлы в каталоге doc/
doc/**/*.txt
```

!!! info "Примечание"
    Указанные здесь названия файлов использованы для примера работы с файлом `.gitignore`

## Коммит изменений (подтверждение)

Для того, чтобы все изменения (за исключением игнорированных и не отслеживаемых) применились, нужно их закоммитить.

Самый простой способ - команда `git commit`

Эта команда откроет выбранный при установке текстовый редактор.

В нем нужно указать комментарий к коммиту, после чего применить и коммит будет создан.

## Работа с удаленными репозиториями

### Просмотр репозиториев

Чтобы посмотреть список доступных настроенных удаленных репозиториев нужно ввести команду `git remote`

Также можно использовать ключ `-v`, чтобы посмотреть адреса для чтения и записи, которые привязаны к репозиторию

### Добавление удаленного репозитория

Чтобы добавить себе удаленный репозиторий требуется та же команда, что и раньше - `git remote`. Но теперь ее нужно использовать немного по-другому.

Добавление репозитория с установкой ему имени делается командой `git remote add <имя> <ссылка>`

После этого можно использовать короткое имя, вместо указания полного пути к локальному репозиторию

### Получение изменений из репозитория

После добавления репозитория нужно как-то вытягивать из него изменения, сделанные другими пользователями

Для этого используется команда `git fetch <имя репоз.>`

Но есть и вторая команда - `git pull`. Использование этой команды активирует fetch и пытается сразу соединить изменения с вашими (активирует merge)

### Отправление изменений в репозиторий

Для отправления своих коммитов на удаленный репозиторий нужно использовать команду `git push <имя репоз.> <название ветки>`

### Просмотр репозитория

Для просмотра более подробной информации о репозитории используйте команду - `git remote show <имя репоз.>`

### Удаление и переименование репозитория

Чтобы переименовать репозиторий используйте команду - `git remote rename <имя репоз.> <новое имя репоз.>`

Чтобы удалить репозиторий используйте команду - `git remote remove <имя репоз.>`

## Ветвление в Git

### Создание веток

Для создания новой ветки в репозитории нужно использовать команду - `git branch <имя ветки>`

Для переключения на другую ветку используется команда `git checkout <имя ветки>`

!!! info "Примечание"
    Можно сразу и создать ветку и переключиться на нее одной командой - `git checkout -b <имя ветки>`

### Слияние веток

Слияние веток происходит в несколько этапов. К примеру есть ветка `master`, но требуется срочно провести какие-то тестовые изменения с исправлением багов. Для этого можно создать доп. ветку `hotfix`.

Как только проведена вся работа в доп. ветке `hotfix` нужно сделать слияние файлов из нее в ветку `master`

Все это делается командой `git merge <название ветки>`

Сначала нужно переключиться на нужную ветку (куда будем переносить) - `git checkout master`

После этого выполнить слияние веток - `git merge hotfix`

Пример вывода:
```
> git checkout master
> git merge hotfix

Updating f42c576..3a0874c
Fast-forward
 index.html | 2 ++
 1 file changed, 2 insertions(+)
```

### Конфликты слияния

Иногда процесс слияния не проходит так легко, как может быть. Если были проведены изменения одной и той же части файла в разных ветках, то Git не сможет провести слияние.

Если такое произошло, то Git остановит процесс до решения конфликта.

Чтобы посмотреть какие файлы не объединились можно использовать команду `git status`

В конфликтующие файлы Git добавляет специальные маркеры, чтобы можно было исправить их вручную

Пример:
```
.<<<<<<< HEAD:index.html
<div id="footer">contact : email.support@github.com</div>
=======
<div id="footer">
 please contact us at support@github.com
</div>
>>>>>>> iss53:index.html
```

`HEAD` - выбранная ветка и ее изменения

Все что ниже `=======` - изменения из вытягиваемой ветки

Здесь остается решение только за вами какое из изменений оставить, а какое удалить, либо же объединить их по-своему

После разрешения конфликтов в файлах нужно запустить `git add` для каждого такого файла, чтобы отметить конфликт как решенный

### Переименование веток

!!! warning "Важно"
    Не переименовывайте ветки, которые все еще используют другие пользователи

Переименовать ветку можно с помощью команды - `git branch --move <старое имя> <новое имя>`

Но это изменение будет только локальным

Чтобы оно применилось используйте команду - `git push --set-upstream <имя репоз.> <новое имя ветки>`

При этом останется и старая ветка на сервере, ее можно удалить командой - `git push <имя репоз.> --delete <старое имя ветки>`

### Удаление веток

Если какие-то ветки, созданные ранее, больше не нужны, то их можно удалять

Для этого нужно использовать команду `git branch` с параметром `-d`

Пример: `git branch -d hotfix`

Для удаления на сервере - `git push <имя репоз.> --delete <имя ветки>`
